# Практика 11. Разработка веб-приложения в соответствии с ТЗ

## Что сделано

1. Фронтенд и бекенд связаны: шаблоны Jinja2 получают данные из сервисных классов (`app/services.py`), те работают с базой через SQLAlchemy.
2. Работа с БД, все четыре действия:
   - мероприятия: администратор добавляет, читает, меняет и удаляет (`/admin/events`); мероприятие с заявками удалить нельзя, показывается сообщение;
   - заявки: участник создаёт, читает, меняет (комнату, оплату, комментарий) и отменяет заявку, пока она новая; после назначения заявка закрыта для правок.
3. Смена статусов: новая, назначено, завершено. Администратор жмёт одну кнопку («Назначить», затем «Завершить»), перескочить или вернуться назад нельзя. Правило проверяет сервер (`ApplicationService.advance`), а не только кнопки.
4. Отзывы: у завершённой заявки появляется ссылка «Оставить отзыв», отзыв виден на странице мероприятия.

Тесты: `pytest tests/test_workflow.py`, 11 тестов, всего вместе с прежними 36.
