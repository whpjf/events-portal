# Практика 12. Доработка структуры БД

## Что сделано

1. Таблица отзывов `reviews` появилась раньше, в практике 9 (миграция `0003`), потому что без неё нельзя было проверить правило «отзыв только после завершения». Здесь добавлена таблица статусов `statuses` (миграция `0004`): `id`, `code`, `name`, `position`, три строки: новая, назначено, завершено.
2. Заявка раньше хранила статус строкой (`status = 'done'`). Теперь в ней `status_id` с внешним ключом на `statuses`. Для кода ничего не изменилось: `application.status` по-прежнему возвращает код статуса.
3. Миграция данных: в `0004` существующие заявки получили `status_id` по старому значению строки, потом колонка `status` удалена. Проверила на базе с настоящими заявками: 5 заявок до и после, статусы совпали (`01-do-tablicy-i-statusy.png` и `02-posle-migraciya.png`). Откат `alembic downgrade 0003` тоже проверила, статусы возвращаются строками.
4. Целостность связей:
   - внешние ключи в SQLite по умолчанию не проверяются, в `app/database.py` включила `PRAGMA foreign_keys = ON` на каждом соединении;
   - одна заявка пользователя на мероприятие (`uq_applications_user_event`), один отзыв на заявку (`uq_reviews_application`), оценка от 1 до 5 (`ck_reviews_rating`);
   - индексы по `user_id`, `event_id`, `status_id`;
   - `PRAGMA foreign_key_check` пустой, `PRAGMA integrity_check` дал `ok`, `alembic check` не видит расхождений между моделями и миграциями (`03-celostnost-i-testy.png`).
5. ER-диаграмма обновлена: `er-diagram-v2.png` и `er-diagram-v2.drawio`.

## Ошибка, найденная при миграции

Первый запуск `0004` на базе с данными упал: `FOREIGN KEY constraint failed` на `DROP TABLE applications`. SQLite пересоздаёт таблицу при изменении колонок, а на неё ссылается `reviews`, и включённые ключи этого не позволяют. Тесты этого не показали, потому что в тестовой базе данные появляются после миграций. Исправила `migrations/env.py`: на время миграции ключи выключаются, после неё выполняется `PRAGMA foreign_key_check`, и при нарушении миграция падает с ошибкой. Базу после неудачного запуска вернула из копии и применила миграцию заново.

Тесты: `pytest tests/test_database.py`, 8 тестов, всего вместе с прежними 44.
