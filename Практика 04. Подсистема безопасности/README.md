# Практика 4. Разработка подсистем безопасности ИС

Код в `portal/`. Что делал и как проверил.

## Что сделано

| Пункт | Как сделано | Где в коде |
|---|---|---|
| Хеширование паролей | argon2 (`argon2-cffi`), в базе только хеш. Миграция `0002` захешировала пароли, которые уже были в базе | `app/security.py`, `migrations/versions/0002_password_hash.py` |
| SQL-инъекции | поиск строился склейкой строки SQL, теперь через SQLAlchemy с параметром; остальные запросы тоже через SQLAlchemy | `app/services.py` |
| Права доступа | гость видит афишу и страницу мероприятия; участник подаёт заявки и видит свои; администратор видит все заявки и меняет статусы. Проверка на сервере, а не только скрытые ссылки | `app/deps.py` |
| Проверка данных | на сервере Pydantic-классы, на клиенте атрибуты `required`, `minlength`, `pattern`, `type=email` | `app/schemas.py`, шаблоны |
| Сессии и cookie | подписанная cookie `konf_session`: `HttpOnly`, `SameSite=Lax`, срок 2 часа, флаг `Secure` включается переменной `PORTAL_HTTPS=1`; при входе сессия очищается и создаётся заново | `app/main.py`, `app/routers/auth.py` |
| CSRF | у каждой формы скрытое поле `csrf_token`, значение хранится в сессии, без совпадения ответ 403 | `app/security.py` |
| Подбор пароля | 5 неверных попыток подряд закрывают вход для этого логина и адреса на 5 минут (ответ 429) | `app/security.py` |
| Заголовки | `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy` | `app/main.py` |

Тесты: `pytest tests/test_security.py` (13 тестов).
