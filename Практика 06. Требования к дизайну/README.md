# Практика 6. Формирование требований к дизайну веб-приложений

## Предметная область и аудитория

Портал «Конференции.РФ» публикует афишу небольших мероприятий (лекции, мастер-классы, прогулки) и принимает заявки на участие. Мероприятия камерные, 15-40 человек, поэтому сайт должен быть простым: выбрал, подал заявку, увидел статус.

Посетителей два вида:

- Участники. Горожане 18-55 лет. Открывают сайт по ссылке из чата или соцсети, чаще с телефона. Им нужно быстро найти мероприятие и отправить заявку за минуту.
- Администратор. Сотрудник организатора, работает за компьютером. Ему нужен список заявок с фильтром и кнопка смены статуса.

Выводы для дизайна: сначала макет под телефон 390×844, потом ширина больше; в формах минимум полей; крупные кнопки; таблица для администратора на телефоне превращается в карточки.

## Корпоративный стиль

Своего фирменного стиля у заказчика нет, поэтому его описываю сама. Логотип только текстовый: слово «Конференции.РФ» шрифтом для заголовков. Тон текстов спокойный, обращение на «вы», предложения короткие.

| Цвет | Код | Где используется |
|---|---|---|
| Чернила | #14161B | текст, основные кнопки, шапка |
| Бумага | #F1F3F5 | фон страниц |
| Белый | #FFFFFF | карточки, поля форм |
| Алый | #C4202F | акценты, ссылки при наведении, метки |
| Светло-алый | #FBE4E6 | подсветка ошибок и выбранного |
| Серый | #5B616B | второстепенный текст |
| Синий | #2B5FA8 | статус «Назначено» |
| Зелёный | #2F7D4F | статус «Завершено» |

Контраст проверила по формуле WCAG: чернила на бумаге 16,3, алый на белом 5,8, серый на бумаге 5,6. Везде выше нормы 4,5.

Шрифты: Unbounded для заголовков и Golos Text для основного текста. Оба с кириллицей, лицензия OFL, файлы лежат в проекте (`portal/app/static/fonts`), с внешних серверов ничего не грузится.

Фотографии настоящие, с Wikimedia Commons. Источники и лицензии записаны в `docs/photo_sources.md`.

## Страницы для дизайна

| Страница | Адрес | Кто видит |
|---|---|---|
| Афиша | `/` | все |
| Мероприятие | `/events/{id}` | все |
| Регистрация | `/register` | гость |
| Авторизация | `/login` | гость |
| Создание заявки | `/events/{id}/apply` | участник |
| Просмотр заявок | `/my` | участник |
| Личный кабинет | `/cabinet` | участник |
| Панель администратора | `/admin` | администратор |

## Требования к страницам

**Афиша.** Карточки с фото, названием, датой и местом. На телефоне одна колонка, на планшете две, на компьютере три. Прошедшие мероприятия помечены и стоят после будущих. Сверху поле поиска.

**Мероприятие.** Крупное фото, дата, место, описание, кнопка «Подать заявку». Для прошедшего мероприятия кнопки нет, вместо неё отзывы участников.

**Регистрация.** Пять полей. Подсказка о формате под каждым полем, ошибка красным рядом с тем полем, где она есть. Кнопка во всю ширину на телефоне.

**Авторизация.** Два поля, ссылка на регистрацию, сообщение об ошибке над формой. Пароль не показывается.

**Создание заявки.** Название и дата мероприятия сверху. Помещение и способ оплаты выбираются из списка, комментарий необязательный. После отправки переход на «Мои заявки» с сообщением.

**Просмотр заявок.** Карточка на каждую заявку: мероприятие, дата, статус цветной меткой. У завершённых заявок кнопка «Оставить отзыв».

**Личный кабинет.** Данные человека (логин, почта, телефон), счётчики: заявок всего, завершённых, отзывов. Ссылки на «Мои заявки» и выход.

**Панель администратора.** Фильтры по статусу, мероприятию и дате над списком. Заявки карточками с кнопками смены статуса. Подтверждение не нужно, статус можно вернуть.

## Общие требования

- Ширина 390 px: ничего не выходит за экран, горизонтальной прокрутки нет.
- Кнопки и ссылки в меню не ниже 44 px.
- Основной текст 16 px, межстрочный 1,5.
- Фото в двух размерах (для телефона и для компьютера), вес картинки на карточке меньше 100 КБ.
- Ошибки не только цветом: у каждой есть текст.
