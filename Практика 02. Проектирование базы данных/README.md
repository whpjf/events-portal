# Практика 2. Проектирование базы данных. ER-диаграмма

Диаграмма нарисована в draw.io (app.diagrams.net). Файлы в этой папке: `er-diagram.drawio` (исходник), `er-diagram.png` (экспорт), `01-okno-drawio.png` (окно программы).

## Сущности

| Таблица | Поля |
|---|---|
| users | id, login (уникальный), password (хеш), email, phone, role |
| events | id, title, event_date, place, description |
| statuses | id, name (новая, назначено, завершено) |
| applications | id, user_id, event_id, status_id, room, payment, created_at |
| reviews | id, application_id, body, rating, created_at |

Первичный ключ у всех таблиц `id`. Внешние ключи: `applications.user_id`, `applications.event_id`, `applications.status_id`, `reviews.application_id`.

## Связи

| Связь | Тип |
|---|---|
| пользователь и заявки | один ко многим |
| мероприятие и заявки | один ко многим |
| статус и заявки | один ко многим |
| заявка и отзыв | один к одному, отзыва может не быть |

Связь «многие ко многим» между пользователями и мероприятиями разбита на две связи «один ко многим» через таблицу заявок: один человек подаёт заявки на много мероприятий, на одно мероприятие приходит много людей.

## Роли

Роль хранится в `users.role` (участник или администратор). Гость это посетитель без входа, в базе его нет.

Таблицы создаются миграциями Alembic, первая из них появится в практике 3.
